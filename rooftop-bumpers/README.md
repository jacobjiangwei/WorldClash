# World Clash 🌍🚗💨

10 车天台卡通碰碰车大混战：**选择代表的国家或地区后加入，为国家赢取全球排行榜积分**。
在一栋高楼楼顶的露天停车场（没有护栏）互相碰撞，把别人怼下楼；击落越多，车越重。

## 玩法

- 选择国家或地区后加入游戏，自动获得一辆车。出生后 3 秒是幽灵状态（闪烁，不会被撞）。
- 入场时可以设置昵称；留空时根据浏览器语言随机取名，不支持的语言使用英文。同名玩家会自动追加编号。
- 电脑：`WASD` / 方向键开车，鼠标滚轮缩放镜头。
  手机：按住屏幕任意处拖动当方向盘（往哪拖，车就往哪开）。
- 车的重心越过楼顶边缘就会掉下去，随后自动从 1 级重新加入。
- 掉楼前 5 秒内最后撞过你的人，算「把你怼下楼」，记 1 次击落（💥）。
- 采用 **10 车单机混战 + 全球国家积分实时联网同步** 模式：你的车与 9 辆 AI 对手完全在本机以 60Hz/120Hz 零延迟运行，每次把对手怼下楼都会为所选国家或地区真实 +1 分并实时同步到云端排行榜。积分每天北京时间 00:00 清零。
- 游戏内偶尔显示 Tinyo Music、BikeX 和 Cinavo 的 App Store 推广卡片；链接配置在 `public/promotions.js`。
- **每击落一辆车升 1 级（最高 20 级）**，存活时间不会升级：体重 +120 kg、车身稍大、最高速 −2.5%。
  - 变重的好处：更难被推走，撞别人更狠。
  - 变重的代价：加速更慢、转向更迟钝、**刹车距离更长**。
  - 所以重车可以被「诱敌」：站在边缘附近引它冲过来，最后一刻闪开，它自己刹不住就冲下楼了。
- 天台始终保持 10 辆车同场混战（1 名玩家 + 9 个各具国家旗帜的 AI 对手）。

## 运行（本机 / 局域网）

只需要 [Node.js](https://nodejs.org) 18 或更新版本。国旗资源来自 MIT 许可的 [flag-icons](https://github.com/lipis/flag-icons)。

```bash
cd rooftop-bumpers
npm ci
node server.js        # 或者 npm start
```

- 自己玩：浏览器打开 <http://localhost:3000>
- 同一个 Wi-Fi 的朋友：打开终端里显示的 `http://192.168.x.x:3000`（如果打不开，检查电脑防火墙是否允许 Node.js 的入站连接）

## 让任何人都能打开（放到公网）

服务器在同一个端口上同时提供网页和游戏连接（WebSocket，路径 `/ws`），部署到任何能运行 Node.js 并支持 WebSocket 的地方即可。端口会自动读取环境变量 `PORT`。

- **临时分享给朋友**：用 Microsoft Dev Tunnels 把本机端口开放出去：
  ```bash
  devtunnel user login
  devtunnel host -p 3000 --allow-anonymous
  ```
  把生成的 `https://…devtunnels.ms` 链接发给别人。注意：这样**任何拿到链接的人都能连到你电脑上的这个端口**，玩完记得关掉。
- **长期运行**：Azure App Service（Node 20+，启动命令 `node server.js`，在「配置 → 常规设置」里确认 Web 套接字已开启），或 Render、Railway、Fly.io 等。
- 只运行**一个**实例：国家积分状态在单实例内同步并持久化到 `DATA_DIR`。
- **线上体验（Feel free to try it, very fun!）**：<https://app-worldclash-dev-39ca.azurewebsites.net/>
  - Azure Resource Group：`rg-worldclash-dev-39ca`（East Asia，免费 F1 计划 `asp-worldclash-dev-39ca`，应用名 `app-worldclash-dev-39ca`）。
  - 更新部署命令：`az webapp deploy --resource-group rg-worldclash-dev-39ca --name app-worldclash-dev-39ca --src-path <zip> --type zip`（基础设施模板见仓库根目录 `infra/`）。

## 配置（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `MIN_CARS` | `4` | 真人不足时用机器人补到几辆车；`0` = 不要机器人 |
| `MAX_PLAYERS` | `100` | 真人上限，满了新玩家会看到「天台挤满了」并自动重试 |
| `MAX_PER_IP` | `0` | 每个 IP 最多几个连接；`0` = 不限。放在反向代理/隧道后面时请保持 `0` |
| `DATA_DIR` | `data` | 国家积分文件目录；部署时需要配置持久化存储 |

例：`MIN_CARS=0 PORT=8080 node server.js`（Windows PowerShell：`$env:MIN_CARS=0; node server.js`）

## 调手感

所有物理和平衡参数都在 `src/sim.js` 顶部的 `TUNING` 里，改完重启服务器即可。常用的几个：

- `massPerLevel`：每级加多少体重（默认 0.12 = 120 kg）
- `brakeExp` / `turnExp` / `accelExp`：体重对刹车、转向、加速的影响（越负 = 重车越笨重）
- `restitution`：碰撞弹性（越大越弹）
- `koWindow`：被撞后多少秒内掉楼算对方的击落

## 联机与流畅度

- 自己的车在本机按 60 Hz 运行与服务器相同的驾驶、障碍物碰撞和掉落物理，按键不再等待网络往返。画面按屏幕刷新率插值；镜头跟随预测位置。
- 入场先测量 RTT，建立独立递增的本地物理时间线。输入按序编号、每两步合包发送。服务器每个物理步最多消费一条操作，回传确认编号、物理帧号与精确自身状态；客户端从服务器帧只重建到当前本地帧，不把「未确认操作数量」误当成还需要推进的时间。网络突发积压时跳过过时的方向采样，最多保留两步服务器缓冲，不排队迟到执行油门。改位置、速度或客户端时间不能让服务器上的车加速。
- 细小校正保持显示位置和速度连续，再用临界阻尼消除偏差，不改变权威物理。镜头只跟随连续的显示位置，不直接使用刚被服务器修正的速度做前视。附近车辆做短时间接触预测，画面随距离逐渐切换到相同的预测时间线，避免“还没看见接触就被撞”；远处车辆仍使用约 67 ms 的快照插值。不可预知的对手操作或严重抖动仍可能产生修正，不能承诺任意网络都完全无感。
- 击落、升级、积分、死亡和重生由服务器决定；本地预测不发放奖励、不自行判死。新生命不会重放上一辆车的操作。
- 失去窗口焦点或切后台立即松开操作。输入历史和待发送队列最多保留一秒，但历史满了不会冻结本地驾驶；恢复连接后的死亡、重生和严重分歧仍以服务器为准。
- 默认使用轻量接地阴影而非实时阴影，限制高 DPI 渲染负担，并在帧率低于约 55 FPS 或帧间隔不稳定时降分辨率。`?low` 可以直接使用最低画质。
- 右下角小角标显示实际加载的客户端内容版本和服务器递增帧号；点击可展开独立的客户端/服务器版本、FPS、最长帧、RTT、远车显示帧、本地渲染帧、输入/确认编号、待确认输入及校正距离。新版本发布后旧页面会提示刷新，不把重连后的服务器版本冒充已加载的客户端版本。`?debug` 默认展开。`/version` 返回服务器版本、进程实例和当前服务器帧号；实例变化表示服务器重启，帧号会重新计数。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `server.js` | 网页 + WebSocket 游戏服务器：物理每秒 60 步，每秒向所有人广播 30 次 |
| `public/sim.js` | 服务器与浏览器共用的物理、碰撞、掉楼、升级、机器人逻辑；`src/sim.js` 为服务端兼容入口 |
| `public/netcode.js` | 定步长输入队列、本地预测、未确认操作重放和显示校正 |
| `src/ws.js` | 零依赖的 WebSocket 服务端实现 |
| `public/game.js` | 浏览器端：three.js 卡通画面、键盘/触屏操作、界面、音效 |
| `public/protocol.js` | 二进制快照协议（服务器和浏览器共用） |
| `public/vendor/three.module.min.js` | three.js r186（MIT 许可，见同目录 `three-LICENSE.txt`） |

## 已知限制

- 断线重连会分到一辆新车，等级不保留。
- 客户端预测不能预知其他玩家的新操作；高延迟、丢包或服务器被免费额度限流时，碰撞仍可能需要校正。
- 低端手机会自动降低画质；也可以在网址后面加 `?low` 直接用低画质。
- 没有聊天或账号。国家选择不做身份验证，公开部署时积分可能被恶意刷取。
- 国家积分保存在 `DATA_DIR/scores.json`。该目录必须使用持久化存储；临时文件系统上的数据可能在部署或重启后丢失。
